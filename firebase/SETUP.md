# Firebase setup for online multiplayer

Everything here is free (Firebase **Spark** plan, no credit card). You do this once.

## 1. Create the project

1. Open <https://console.firebase.google.com> and sign in with a Google account.
2. **Add project**, give it a name (e.g. `tic-tac-toe-online`). You can switch Google Analytics off.

## 2. Turn on guest sign-in (no accounts for players)

**Build → Authentication → Get started → Sign-in method → Anonymous → Enable.**

Each browser gets an anonymous ID that survives page refreshes. That ID is what keeps a player's seat in a room.

## 3. Create the database

**Build → Realtime Database → Create database.** Pick the region closest to your players, and start in **locked mode**
(the rules below replace it).

## 4. Publish the security rules

**Realtime Database → Rules tab →** delete everything, paste the contents of `database.rules.json`, press **Publish**.

> **Whenever you get a new version of this project, paste `database.rules.json` again.** The rules and the game code are
> a matched pair, and an old copy of the rules will refuse newer features. **This version changes the rules** (watching a
> match as a spectator, and winning by abandonment for either player), so you must republish them before testing.

**Publishing new rules safely**

1. In the console open **Realtime Database → Rules** and copy the rules that are there now into a text file (your backup).
2. Replace them with the new `database.rules.json` and press **Publish**. Nothing else needs changing: your data stays put.
3. Rooms created before the update keep working. They simply have no spectators yet.
4. Check it with the **Rules Playground** (below), then try the two-device checklist.
5. If anything looks wrong, paste your backup back and press Publish: you are back where you were.

These rules are what stop cheating (wrong turn, illegal cell, wrong board, faked results, early forfeit). They are generated by
`build-rules.js`. Do not edit the JSON by hand; change the generator and run `npm run build`.

## 5. Allow your website

**Authentication → Settings → Authorized domains → Add domain:** `YOUR-USERNAME.github.io`
(`localhost` is already there for testing on your own computer).

## 6. Copy your web app settings (needed for the next stage)

**Project settings (gear icon) → General → Your apps → Web (`</>`) → Register app**, then copy the `firebaseConfig` block.
It looks like this and must include `databaseURL`:

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "your-project.firebaseapp.com",
  databaseURL: "https://your-project-default-rtdb.firebaseio.com",
  projectId: "your-project",
  appId: "..."
};
```

These values are not secrets (they are visible in any website's source). The security comes from the rules above.

## Spark plan limits to know about

| Limit | Value | What it means for you |
|---|---|---|
| Simultaneous connections | 100 | About 50 games being played at the same moment |
| Stored data | 1 GB | A finished room is about 2 KB, so this is huge |
| Downloaded data | 10 GB / month | Plenty for a small game |

If the limits are hit, Firebase just stops accepting new connections until it resets. It never bills you on Spark.

## Try it with two or three devices (do this after steps 1 to 5)

1. Upload the project to GitHub Pages as usual (the `firebase/` folder is not needed there, but it does no harm).
2. **Play:** on your computer open a game page, choose **Online**, press **Create room**. On your phone choose **Online**, type
   the code, press **Join** (or use **Share link**). The host is X and moves first.
3. **Ultimate colours:** the player to move sees the playable board(s) with a solid **green** border, the other player sees
   them **yellow** (dashed). When a move sends you to a finished board, every open board is highlighted.
4. **Refresh test:** refresh one device mid-game. It should land back in the same room with the same position.
5. **Disconnect test:** close the phone's tab. The computer shows *"Opponent disconnected. Waiting for reconnection: 01:59"*
   and the board locks. Reopen the page within 2 minutes and the game resumes. Stay away for 2 minutes instead and the
   computer's player wins automatically (this works for the host and for the guest).
6. **Home button:** press **Home** in the middle of an online match. You get *"Are you sure you want to leave? Your opponent
   may win if you don't return within 2 minutes."* Cancel keeps you in. OK starts the opponent's countdown at once. Come back
   to the page (Online mode) within 2 minutes to resume. In local and Computer modes Home just goes home.
7. **Spectators:** on a third device choose **Online**, type the code, press **Spectate**. You see the board live with a
   "Spectator Mode" label and cannot move. A 4th spectator is refused ("Spectators: 3/3"). A spectator leaving frees the slot.
8. **End of game:** a win draws an animated line through the three cells, the winner gets *Congratulations! You Win!* with
   confetti, the loser *You Lost!*, and **Reset** (offline) or **Rematch** (online) pulses. Press **Rematch** on one device
   and **Join rematch** on the other; spectators see **Watch rematch**.
9. **Easter egg:** on the home page click the word "Toe" in the big title three times quickly.

If **Create room** says the rules aren't published, or guest sign-in is switched off, the message tells you which step to redo.

## Automated tests

```
cd firebase
npm install
npm run test:all   # rules, client, lobby, gameplay, features, effects and home page tests (about 40 seconds)
npm run fuzz       # corrupts moves at random and checks that none get through (about 2 minutes)
```

| Command | What it checks |
|---|---|
| `npm test` | Honest games are accepted by the rules; dozens of hand-written cheats are rejected |
| `npm run test:client` | Two simulated browsers play full games through `MultiplayerClient.js`: refresh recovery, the 120 s grace period, host-away pause, code collisions |
| `npm run test:panel` | The lobby screen on the real pages: create, join, share links, countdown, errors |
| `npm run test:play` | Two simulated devices play real games by tapping: turns, board highlights, pauses, refresh, claiming a win, rematch |
| `npm run test:features` | Home-as-leave, spectators (limit, refresh, leave), green/yellow highlights for every role, both players dropping |
| `npm run test:effects` | Winning lines, win / lose / draw banners, confetti, reduced motion, once-per-match, glowing buttons |
| `npm run test:landing` | The home page Easter egg |
| `npm run fuzz` | Takes honest moves, corrupts one thing, and expects the rules to refuse |

These run against **targaryen**, a Firebase rules simulator. It is not Firebase itself, so before launch also try a couple of
cases in the console: **Rules tab → Rules Playground** (choose "Authenticated", set a UID, location `/rooms/ABCD23`, run a *write*).

## What the rules enforce

| Rule | How |
|---|---|
| Players are guests | Anonymous sign-in; the room remembers each player's anonymous ID |
| Private rooms | Rooms can't be listed, only opened by someone who knows the 6-character code (about a billion possible codes) |
| Only 2 seats | The creator is seat X; one other person can claim seat O, once |
| Out-of-turn moves | A move is only accepted from the player whose turn it is, and only when both players are online |
| Illegal moves | Cell must be empty; Ultimate: must be in the board the last move pointed to (or anywhere after a free turn); no play in won/tied boards |
| Faked results | Small-board wins/ties, whose-turn-next, board counts and the game winner are all re-checked from the cells themselves |
| Reconnect window | Presence is recorded with the **server's** clock; the host can only claim a forfeit once the server says the guest has been away 120 s |
| Host away | The game pauses (no moves accepted) until the host returns; the guest cannot claim a win against the host |
| Deleting / editing history | Marks and results can never be changed or removed once written; only the host can delete the whole room |
| Abandonment | The player who is still connected wins after the other has been away 120 s on the **server's** clock, for either seat. The claim is only valid if they stayed connected since before the opponent dropped, so when both drop nobody can win. One result only |
| Spectators | At most 3, in three fixed slots that are claimed by writing to them (two people racing for the last slot cannot both get it). Watchers can read the room but cannot write moves, presence, seats or results. A dropped watcher's slot is reserved for 30 s, then can be reused |
| Rematch | Either player can point a finished game at a new room they created. The pointer can be written once and only after the game is over |
